## 2. Подтверждено запуском / анализатором

### 2.1 Неверный поворот для A3x4 портрет — строка 1129 `[АНАЛИЗ]`
В `Sbugo-set-layout-type-printer` у всех 26 пар «альбом/портрет» портретная строка меняет `ac0degrees ↔ ac90degrees`. Строка 1129 — копия 1128 без смены:
```lisp
((and (equal ViewportHight 1189 1.1) (equal ViewportWidth 420 1.1)) (SBUGOPDCONFIGSSETINGLAYOUT "14")
  (setq return (Sbugo-local-set Layout (if (= sbugoPDAngleOfRotation "ac0degrees") ac90degrees ac0degrees))))
```
Анализатор (раздел 8a в [lint_report.txt](lint_report.txt)) находит ровно одну несимметричную строку; тот же результат даёт снимок таблицы в тестах (`INFO SNAPSHOT of the old COND … ("14" 1189.0 420.0)`). Это проверка **текста** `cond`: сам `cond` на реальном листе не запускался (нужен ActiveX/GUI). Асимметрия — единственная из 27 пар, поэтому почти наверняка опечатка копирования.

### 2.2 Опечатка в INI: A4 = 210×**291** — строки 88 и 142 `[ТЕСТ]`
Должно быть 297. Сейчас на работу не влияет (размеры сопоставляются по жёстко зашитой таблице), но вводит в заблуждение и сломается при переходе на таблицу из INI.

### 2.3 Вложенный `defun` подменяет глобальную функцию — строки 551 и 592 `[АНАЛИЗ][ИЗМЕРЕНО]`
`Sbugo-addlay-Error-read` объявлена на верхнем уровне (1692), но дважды определяется **внутри** `SBugo-AddLay`. Имени нет в списке локальных переменных, поэтому при каждом прогоне, который доходит до проверки имён листов (ветка «NO» и режим «Разобрать лист»), глобальная версия заменяется упрощённой (без работы с `cmdecho`). Тест: после выполнения внешней функции вложенная становится глобальной. Удалить вложенные копии.

### 2.4 Утечка глобальных переменных `[АНАЛИЗ]`
62 символа присваиваются без объявления локальными. Часть — намеренные настройки (`sbugoPD*` из диалога, `G_*`), но случайные нужно сделать локальными:
`Format` (442), `lst` (782), `oldEcho/old1Echo/old2Echo`, `sbugoDcl_IdNumber`, `sbugoDdiStatus`, `sbugoErrDdiStatus`, `sbugoReEnterDcl_IdNumber`, `sbugoPDIDOpen*IniFile`, `sbugoPDNameRead/WriteIniFile`, `sbugoPDSpisok_Temp`, `sbugoPDNamesLayerFoForms`, `sbugoPDNamesLayerFormsForBlock`, `sbugoPDTempIncrement`, `sbugoPDTempMin/MaxPoint` (2778), `sbugoPDListAllCopyInsertObject`, `sbugoPDOffsetData`, `sbugoPDNumDelete`, `sbugoPDNumStylePrint`, `SbugoPD_temp_unique_alert`.
Проверено: переменная цикла `foreach` **восстанавливается**, так что `item` — не утечка.

### 2.5 Опечатки, которые парсятся без ошибок, но неверны `[АНАЛИЗ]`
- **1668** `(Т "")` — буква **кириллическая** (U+0422), а не латинская `T`. Ветка по умолчанию в `cond` не работает (безвредно: дальше есть проверка).
- **1726, 2080, 2185, 2189**: `\\ если нажали ентер…` — это **не комментарий** (комментарий в LISP — `;`). Слова читаются как символы и вычисляются в `nil`. Грузится без ошибок, но заменить на `;`.
- **2127** `(set_tile "dclSbugoPDScaleLineweightsn" …)` — лишняя `n`; в DCL ключ `dclSbugoPDScaleLineweights`. Настройка «Масштабировать веса линий» **не восстанавливается** при повторном открытии диалога.
- **1836** `alignment = rigth;` (DCL) — нет такого значения.
- **2007–2010** `value = 0;` без кавычек (в DCL `value` — строка).
- **2085** в callback-строке лишняя закрывающая `)` в конце.
- **376, 519, 539, 549, 590** — `initget` без последующего `get*`: ничего не делает.
- **441** — лишнее выражение `(ssname Formats i)` в начале тела `repeat` (результат не используется).

### 2.6 Размеры листа: `fix` вместо округления — строки 853–854 `[ИЗМЕРЕНО]`
`(fix 295.9)=295`, `(fix 298.9)=298`. С допуском ±1.1 мм реальное окно приёма для A4 получается **[296; 299)** вместо [295.9; 298.1]: 298.9 принимается, 295.9 — нет. Заменить на округление: `(fix (+ x 0.5))`.

### 2.7 `wcmatch` зависит от регистра — строки 364, 2046, 2049 `[ИЗМЕРЕНО]`
`(wcmatch "ACAD.CTB" "*.ctb")` → `nil`. Стиль печати с расширением в верхнем регистре молча заменяется на «нет стиля». Обернуть в `(strcase …)`.

### 2.8 Две рамки с одинаковыми границами — строки 498–499, 727–729, 808, 910 `[ИЗМЕРЕНО]` + `[ЧТЕНИЕ]`
- `vl-sort` **схлопывает полностью идентичные** элементы (рамки с разными координатами — не теряет; это проверено отдельно). При дубликате рамки `(length Points)` < `NumberFormats`, и на последнем листе `(nth j Points)` = `nil` → ошибка.
- `(vl-position (nth j Points) PointsNoSort)` для дубликатов всегда возвращает первую рамку (масштаб, `CHSPACE`, параметры берутся не у той).

### 2.9 INI: хрупкий формат и тихие ошибки `[ТЕСТ]`
- Заголовок строго 55 строк, запись — 9 строк; усечённый или отредактированный файл даёт список с `nil` **без предупреждения** (тест `loader detects a truncated/corrupted INI`).
- Ориентация/плоттер ищутся через `member` по номеру позиции — ломается, если любое поле равно номеру.
- Лучше: разбор по маркерам `*****`, проверка числа записей, возврат к значениям по умолчанию с сообщением.

Работает: генерация (542 строки), чтение (432 элемента), уникальность ключей 01–27 и 101–127, все 54 записи разрешаются. Тестами это закреплено.

### 2.10 Дубли кода `[АНАЛИЗ]`
- Две таблицы по 54 условия: 1102–1155 и 1262–1315 (идентичны, проверено) → ~110 строк.
- Два одинаковых `while` проверки имён: 546–580 и 587–621.
- Блок параметров листа: 862–881 и 1422–1441.
- Копии `*error*` — 19 штук, в одной (1696) в сообщении неверное имя функции.

## 3. Выведено из кода (в консоли не проверить)

### Состояние пользователя и откат при ошибке `[ЧТЕНИЕ]`
- **LayoutCreateViewport** (`Preferences.Display`) выключается в 514 и возвращается только в 983. Обработчик `*error*` (353–358) этого не делает → после любой ошибки между этими строками новые листы у пользователя **навсегда** создаются без видовых экранов (настройка хранится в профиле).
- **Внутренние `*error*` перекрывают внешний.** Ошибка в `GetBoundingBox_dynblock`, `MinElement`, `SBugo-Get-InsertPoint-…` и т. п. обрабатывается их собственным обработчиком — `INSUNITS` (меняется в 429, возвращается в 506) остаётся равным 4.
- Не возвращаются: UCS (822–839 и 2709), блокировка слоя рамок (400/1006), закрытие undo-метки, `PSLTSCALE` (723), `CANNOSCALE`, `ANNOALLVISIBLE`/`ANNOAUTOSCALE` (890/897), `CMDECHO` в `C:SBADDLAY`.
- **Undo:** метка ставится на 389–422 и 980–1011, а вся работа (424–979) — вне группы; одним `U` не откатить. При ошибке метка не закрывается.
- `sbugoPDLayerNoBlock` / `sbugoPDNameOldCurrDefoltLayer` не очищаются после успешного завершения (см. пункт 3 в разделе 1). Конкретный сценарий: после первого успешного запуска нажать Esc на запросе «Укажите объект…» (386) — вас перебросит на вкладку «Модель».
- `(exit)` (236, 1352, 1724, 2029, 2650, 2677) идёт через эти же обработчики и печатает «Программа допустила ошибку…».

### Диалоги `[ЧТЕНИЕ]`
- `Sbugo-allert-reenter-list-insert` (1712): результат `start_dialog` не возвращается/не проверяется; Cancel оставляет старый номер → цикл 546–580/587–621 повторяет диалог. Нужен выход (флаг + `(exit)`).
- Проверка значений в `action_tile` срабатывает только при уходе из поля; кнопка ОК принимает 0/мусор. Проверять в `Sbugo-addlay-read`.
- 2197: `getfiled` по Cancel возвращает `nil` и **затирает** `G_SbugoPDDefaultSelectIniFile`.
- `C:SBADDLAY`-обработчик не вызывает `unload_dialog`.
- `slide_image` (2205–2229) без защиты: файл `Sbugo_addlay_insert.slb` в присланной папке отсутствует; при его отсутствии `end_image` не будет вызван.
- Стартовое значение поля INI показывает путь разработчика `C:\sbugo\0_LISP\…` (1836, 2087), пока конфиг не прочитан.

### Листы и рамки `[ЧТЕНИЕ]`
- 524–538: листы удаляются **внутри** `vlax-for` по той же коллекции — риск пропуска элементов. Надёжнее собрать имена, затем удалять.
- 568, 609: `member` сравнивает имена листов **с учётом регистра**, а AutoCAD — без учёта → «LIST 1» и «list 1» не найдутся как совпадение, и `vla-Add` упадёт.
- 413, 993, 3038 (`-LAYER`) и **435** (фильтр `ssget` по `(cons 8 Layer)`): имя слоя воспринимается как маска (`#`, `@`, `.`, `~`, `[]`) — слой с такими символами замораживается/выбирается неточно или задевает чужие. Для заморозки использовать свойство `Freeze` (ActiveX) или `entmod`, в фильтре `ssget` экранировать спецсимволы.
- 435: `ssget` с одним фильтром — интерактивный выбор без своего приглашения; пустой выбор → 436 падает.
- 727–735: отрицательный `XScaleFactor` (зеркальная рамка) даёт отрицательный масштаб → высота/ширина = 1.
- 1587–1600: границы динамического блока не учитывают поворот.
- 2397–2398, 3213–3214: `GetBoundingBox` возвращает WCS, а затем применяется `(trans … 1 0)`; при не-мировой ПСК координаты искажаются.
- 3057–3220: учитываются только `LWPOLYLINE/LINE/POINT/MLINE`, вложенные блоки без своих трансформаций.
- 918–920: поля рамки ГОСТ (25/10/7.5 мм) зашиты в код.
- 844, 907, 937: в булево свойство `DisplayLocked` передаётся **строка** `"-1"`/`"1"`; комментарий «разблокировка» к `"1"`, скорее всего, неверен (строка `"1"` приводится к True). Использовать `:vlax-true/:vlax-false`.
- 3469–3483: результат `entmake` не проверяется; при неудаче `entlast` вернёт чужой объект, который затем получит слой `Defpoints` (958) или будет стёрт (930).

### «Собрать лист из листов» `[ЧТЕНИЕ]`
- 2772: затравка `'((0 0 0) (1 1 0))` тянет минимум габарита в начало координат; вспомогательная функция и так обрабатывает `nil`.

- `_move` пропускает объекты на заблокированных/замороженных слоях без сообщения.
- 2709/2891: `UCS W … UCS P` не восстанавливается при Esc (обработчик чинит только OSMODE).

### Прочее `[ЧТЕНИЕ]`
- **Хранение настроек** в TEMP (20–31, 222–229): `Storage Sense`/очистка TEMP сотрёт ИНИ; DCL-путь на 1782 склеен без разделителя (в INI-коде есть `vl-string-right-trim`).

## 4. Гипотезы, которые я проверил и **отбросил** (не тратьте на них время)

- «`vl-sort` теряет рамки с одинаковым X/Y» — **нет**, теряет только полностью идентичные элементы (2.8).
- «`(> nil 0)` падает в `SbugoPD-special-characters-name-new-block`» — **нет**, возвращает `nil`; функция тестами проходит (13 символов, повторы, `CMDECHO`).
- «Параметр, он же локальный, затирается в `sbugoPDVpoInsert`» — **нет**: `(defun f (a / a))` возвращает значение параметра.
- «Пара `UCS W … UCS P` (2709/2891) уводит пользователя в старую ПСК» — **нет**: я записывал `UCSORG` на каждом шаге — после `UCS O 5,5,0` → (5,5,0); `W` → (0,0,0); повторный `W` и затем `P` → остаётся (0,0,0). Реальная проблема другая — при Esc/ошибке `UCS P` просто не выполняется (раздел 3).
- «Константа 17051 не совпадёт на другой версии AutoCAD» — **совпадает** на 2016, 2017, 2024, 2026 (cp1251, CRLF): DCL пересоздаётся только при изменении текста.
- «Файл не грузится из-за `\\`-псевдокомментариев и кириллической `Т`» — грузится: скобки сбалансированы, 31 форма верхнего уровня, ошибок чтения нет.

**Вторая очередь**
6. Таблица форматов — из INI, одной функцией (протестировано: воспроизводит все 54 условия, поворот симметричен по построению, допуск ±1.1; новые форматы добавляются строкой в INI):
```lisp
(defun sbugo:find-format (h w tbl / hit)          ; tbl = ((pos s1 s2) ...), s1 < s2
  (foreach r tbl
    (if (null hit)
      (cond ((and (equal h (cadr r) 1.1) (equal w (caddr r) 1.1)) (setq hit (list (car r) T)))
            ((and (equal h (caddr r) 1.1) (equal w (cadr r) 1.1)) (setq hit (list (car r) nil))))))
  hit)                                             ; -> (pos landscape-p)
(defun sbugo:rotation (ini-rot landscape-p)        ; портрет всегда меняет ориентацию из INI
  (if (eq (= ini-rot "ac0degrees") (not (not landscape-p))) 0 1))
(defun sbugo:iround (x) (fix (+ x (if (minusp x) -0.5 0.5))))
```
Это заменяет ~110 строк двух `cond` и устраняет класс ошибок вроде 1129.
7. Заморозка слоёв свойством `Freeze` со снимком состояния вместо сотни `command "-layer"`; без `REGENALL` на каждом запуске.
8. Удаление листов: собрать имена → удалять; сравнивать имена через `strcase`; одна undo-группа на всю операцию.
9. Имена масштабов: для s ≥ 1 — `1:N` с `(rtos s 2 6)` без хвостовых нулей, для s < 1 — `N:1`; кэш списка масштабов — локальный, на один запуск. *(Идея, **не тестировалась**: вывод `rtos` может зависеть от `DIMZIN` — проверьте хвостовые нули.)*
10. INI: в `%APPDATA%` (не TEMP), номер версии в первой строке, разбор по маркерам, валидация, понятное сообщение.
11. DCL: либо лежит рядом файлом, либо пишется один раз в постоянное место; путь собирать через `(strcat (vl-string-right-trim "\\" dir) "\\…")`.

12. Разделить файл: конфиг / диалоги / построение листов / принтеры / утилиты; настройки хранить одним assoc-списком вместо ~40 глобальных переменных.

## 6. Тесты

**Автоматические** — [Sbugo_addlay_insert_tests.lsp](Sbugo_addlay_insert_tests.lsp) (ASCII, без диалогов и ActiveX):
```
(load "Sbugo_addlay_insert.lsp")
(load "Sbugo_addlay_insert_tests.lsp")
(sbt:run)
```
Метки: `PASS`; `FAIL` — регрессия; `BUG` — дефект плагина, найденный запуском его кода (после исправления станет `FIXED`); `INFO` — измеренный факт об AutoLISP или снимок исходника (после правки плагина не меняется); `NOTE` — наблюдение; `SKIP`.
Симметрию таблицы поворотов (строка 1129) после правки проверяйте `lsp_lint.py` (раздел 8a), а не этими тестами.
В окне AutoCAD группа «INI» пропускается (она записывает ваш реальный `Sbugo_addlay_insert.ini` в TEMP) — запускайте её в консоли.
Текущий результат: `pass=65 fail=0 known-bugs-present=2` (+ строки `INFO`/`NOTE`).

**Статический контроль** — [lsp_lint.py](lsp_lint.py) + [atoms_builtin.txt](atoms_builtin.txt) (список встроенных функций AutoCAD 2026; должен лежать рядом со скриптом): `python lsp_lint.py Sbugo_addlay_insert.lsp -o report.txt`. DCL анализатор извлекает из исходника сам. Проверяет скобки, утечки переменных, ключи DCL, симметрию таблицы форматов.
Возможные ложные срабатывания: локальные функции в списке «dead locals», если они только передаются по имени; символы, создаваемые лишь через `set`/`eval`. Кириллические слова в разделе «опечатки» — это и есть найденный дефект 2.5 (псевдокомментарии после `\\`).

**Ручной чек-лист для интерактивной части** (в окне AutoCAD, на копии чертежа):
1. 3 рамки A3 в ряд, масштаб 1:50, «Автоматически» выкл → 3 листа, имена, размер ВЭ, масштаб.
2. Режим автоопределения масштаба с блоком-рамкой `XScale=100` и с масштабом 2.5.
3. Рамка, повёрнутая на +10° и −10° («Правый край выше/ниже оси X»).
4. Рамка — динамический блок; рамка — полилиния; рамка в блоке.
5. Дубликат рамки в одном месте (ожидаем осмысленное сообщение, не падение).
6. Портретная A3x4 (1189×420) и все 27 форматов в обеих ориентациях — сверить `PlotRotation`.
7. «Удалить существующие листы» при 5+ листах.
8. Совпадение имён → ввод нового номера; **Cancel** (сейчас — зацикливание).
9. Искусственная ошибка (префикс листа из пробелов/запрещённых символов, масштаб 0) → потом проверить: настройка «Создавать видовой экран при создании листа» (OPTIONS), `CMDECHO`, UCS, блокировка слоя рамок, текущая вкладка.
10. Esc на запросе «Укажите объект…» после успешного запуска (сейчас — переброс на «Модель»).
11. Включённые привязки (`OSMODE=4133`) и ПСК не World.
12. Слой рамок заблокирован/заморожен; слой с именем, содержащим `#` или `@`.
13. Пустой выбор рамок (Enter).
14. «Разобрать лист» и «Собрать лист»; режим переноса рамки (`CHSPACE`) и подрезки ВЭ.
15. Повторное открытие диалога: все флажки восстанавливаются (в т. ч. «Масштабировать веса линий»).
